# Wi-Fi CSI 변경 및 검증

관련 문서: [CSI 개발 문서](https://app.notion.com/p/CSI-a080797e801c4a31a3fe03d9efd5e3b5), [통합 검증](UI_INTEGRATION_VALIDATION.md), [실제 모드 안내](REAL_MODE.md)

## SafeHub 통합

수어 인식 홈에 Wi-Fi 센싱 화면을 추가했다. 최신 52채널/PCA 1성분 엔진을 사용하여 실시간 파형, 행동 기록, 선택 학습과 현재 행동 판단을 연결한다. PC에서 학습하고 Pi에서 수집·전처리·추론하는 역할을 유지한다. 기존 MQTT Topic/JSON과 전처리·기록·모델 규격은 변경하지 않는다.

장비 주소는 연결 설정에서 저장한다. 미설정 상태에서는 화면을 열고 연결을 대기하며, 정상 저장 후 새 설정을 적용한다. API 키는 별도 ENV 파일에 저장한다. 실제 모드는 모의 CSI 요청을 거부하고 모의 입력을 허용하는 서비스의 결과도 표시하지 않는다.

## 연결과 오류 처리

- 카메라는 온전한 프레임 수신 후 연결 상태를 표시한다. 불완전한 데이터로 영상 유효 시간을 연장하지 않으며 잘못된 길이의 프레임 수신 시 재접속한다.
- CSI는 수신 공백·연결 해제 시 파형과 판단을 초기화하고, 재연결·시간 변경 때 이전 수집을 완료 처리하지 않는다. 시리얼 분할 수신과 과대 입력을 처리한다.
- 손상된 메타데이터는 원본을 보존하고 목록에서 제외한다. 학습·모델 교체·인식 시작의 경합을 제한하며 지연된 응답이 최신 상태를 덮어쓰지 않게 한다.
- MQTT는 최초 실패 재시도, 중복 연결 방지와 종료 후 늦은 응답을 처리한다. UI는 작은 화면, 녹음 권한·취소·종료 경합과 설정 저장 실패를 처리한다.
- Windows 오디오 플러그인의 이벤트 처리기 이중 소유권은 호스트 vendor 복사본에서 수정한다. 원본 패키지·ATLAS 코드·라이선스는 보존한다.

## 처리 비용

카메라 고정 수신 버퍼, CSI 최신 구간 복사와 동일 입력 캐시, 파일 변경 기반 기록·모델 목록 갱신을 적용했다. I/Q 입력의 JSON 생성·AST 재파싱을 NumPy 배열 변환으로 교체하되 52채널 매핑·타임스탬프·전처리·CNN 입력은 유지한다. 복사 당시 원본과 변경 해시를 함께 검사한다.

Windows 합성 입력 측정에서 I/Q 변환 중앙값은 152.63→10.58ms, 4초 구간 전처리는 212.93→52.09ms였다. 수신·화면·Pi 성능이나 실측 행동 정확도를 포함하지 않는다. 측정 조건과 원자료는 [통합 검증](UI_INTEGRATION_VALIDATION.md)에 기록한다.

## Windows 전달본

개발 도구 없이 실행하도록 내장 Python·CPU PyTorch와 의존성을 포함한다. 상대 경로, UTF-8, 초기 준비 대기와 격리 실행을 지원한다. 로컬 CSI 주소와 서비스는 8768 포트를 사용한다. 개인 기록·모델·로그·접속 정보는 제외하고 소스 출처·라이선스·변경 명세를 유지한다. 기존 WifiSensing 실행본과 사용자 기록은 별도로 보존한다.

모델 ZIP 내보내기는 출처·변경 명세를 포함하고 완성된 ZIP만 교체한다. 실패 시 이전 ZIP을 유지한다.

## 검증 요약

| 검사 | 결과 |
| --- | --- |
| Python 및 내장 런타임 | 각각 44개 통과: 선택 학습, 전처리 동등성, 모델 ZIP, PC/NumPy 추론, 오류 처리 |
| Flutter 호스트 | 전체 135개, 별도 체험 모드 홈 3개 통과 |
| Windows 패키지·실행기 | 패키지 준비 4개, 오디오 패치 준비 7개, C# 설정 검사 통과 |
| 20분 합성 연속 실행 | 72,001프레임·평균 59.997Hz·HTTP 조회 2,400회, HTTP 오류·stale poll 없음 |
| 전달 ZIP | CRC·SHA-256, 압축 해제본의 파일·경로·입력 동등성 및 최종 실제 모드 서비스 확인 |

카메라·MQTT 연결 검사는 loopback 서버와 시험 브로커로 수행했다. 전달본은 동일 Windows 노트북에서 이동·압축 해제하여 검사했으며 최종 격리 옵션 적용 후 GUI 재실행, 별도 초기화 PC 실행, 실제 C6·Pi·카메라·스피커 동시 운전은 미검증이다. 합성 학습 점수는 실제 행동 정확도가 아니다.

실물 수신·복구, Pi 자원 사용과 장시간 운전, 독립 실측 데이터 정확도·오탐, 팀 MQTT·안전 경보 통합은 장비 검증 항목으로 남긴다.

## 소스와 제출 기준

독립 CSI 모듈은 팀 프로젝트의 `WiFi-CSI-Sensing`에 배치한다. 형식 정리는 PEP 8과 snake_case를 기준으로 하며 규격·처리 로직을 보존한다. 최초 형식 정리의 기능 검사 194개·Ruff 결과와 24개 Python 파일의 AST 비교는 [기준 검증](VALIDATION.json)에 보존한다. 현재 통합본의 검증 범위는 위 표와 통합 검증 문서를 따른다.

기준 소스와 라이선스는 [런타임 출처](../../SW/wifi_sensing/runtime/NOTICE.md), [MIT 라이선스](../../SW/wifi_sensing/runtime/LICENSE), [제3자 고지](../../SW/wifi_sensing/runtime/THIRD_PARTY_NOTICES.txt)에 기록한다. 제출은 개인 fork의 `feature/wifi-sensing-ui`에서 팀 `develop` 대상 Draft PR로 진행하며, `main`에 직접 push하거나 PR을 병합하지 않는다. 기반 `feature/SW`와 CSI 통합 변경은 구분하여 검토한다.
