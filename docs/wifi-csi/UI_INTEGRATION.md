# 수어 UI + 최신 노트북 CSI 통합

작성: 2026-10-04 (Asia/Seoul). 상태: 장비 연결 전 개발, 실기기 배포 미검증.

## 기준과 역할

- UI 기준: 팀 `feature/SW`의 기존 SafeHub Flutter 화면. 기존 수어·가전·알림 흐름을 유지하고 센싱 페이지를 추가한다.
- CSI 기준: 노트북 `WifiSensing2-src`의 현재 소스를 별도 runtime 폴더에 복사한다. 파일별 SHA-256을 기록한다. 기존 EXE와 원본 데이터는 수정하지 않는다.
- 최신 파이프라인: 52개 채널, DWT → 표준화/PCA 1성분 → FFT 저역 통과, 4초/240시점. 같은 함수를 관찰·학습·추론에 재사용한다.
- I/Q 입력은 숫자 배열에서 진폭으로 변환한다. 기존 문자열 변환기와 변경 해시를 보존하고, 표시·학습·추론 입력의 수치 동등성을 검사한다. 전처리 수치와 모델 구조는 유지한다.
- PC: 수집, 기록 선택, 학습, 모델 내보내기. Pi: 수집, 전처리, 추론. Pi 모드에서는 학습 요청을 거부한다.
- 기존 MQTT Topic/JSON을 변경하지 않는다. 이번 로컬 제어 API는 UI와 CSI 프로세스 사이의 통신이며 팀 장치 간 MQTT 규격을 대체하지 않는다.

## 구조

SafeHub Flutter 페이지 → 같은 기기의 loopback HTTP 제어 API → 최신 CSI Python 엔진.
카메라/수어 프로세스는 기존대로 별도로 실행한다. CSI 처리 때문에 카메라나 화면을 블로킹하지 않는다.
UI 종료·페이지 이동은 수집을 종료하지 않는다. 명시적 수집 취소/연결 해제와 프로세스 종료를 구분한다.

## 이번 작업의 검증 범위

장비 없이 synthetic CSI의 수집·전처리 토글·선택 학습·모델 추론 경로를 검증한다. 모의 데이터는 별도 영역에 저장하고 실측 모델과 혼합하지 않는다. 모의 인식 결과를 안전 경보로 발행하지 않는다.
신호가 끊기면 이전 파형/행동을 지우고 대기 상태로 전환한다. USB 재연결 또는 장치 시간 초기화 시 진행 중 수집을 취소한다.
실시간 버퍼는 제한하며, 무제한 원본 저널을 만들지 않는다. 사용자가 요청한 구간만 저장한다.

## 실제 장비 연결 후

사용자가 준비한 연결 장비: 외부 터치디스플레이, 라즈베리파이, 카메라, 스피커. Pi OS와 각 장치의 연결 방식은 실물 연결 시 확인한다.

1. Pi 모델·RAM·64비트 여부·OS(ATLAS/webOS 또는 Raspberry Pi OS)를 확인한다. OS 확인 전 이미지/펌웨어를 덮어쓰지 않는다.
2. 기존 수어 앱을 해당 OS의 도구로 빌드하고 카메라를 확인한다. 현재 pubspec에는 `/opt/flutter-atlas-plugins` 의존성이 있다.
3. C6 RX를 USB로 연결하고 펌웨어 출력과 최신 52채널 입력 호환성을 확인한다.
4. PC에서 내보낸 모델을 Pi에 배포하고 동일 입력의 PC/Pi 전처리·추론 결과를 비교한다.
5. 동시 실행 지연·CPU/RAM·수신 공백·USB 분리/복구·장시간 운전을 측정한다.
6. MQTT 이벤트 이름/우선순위 매핑과 v1.2 승인 상태를 팀과 확인한 후 안전 알림·액추에이터 연결을 활성화한다.
7. 개인 feature 브랜치에서 develop 대상 PR을 제출하고 팀원 검토를 받는다. main 직접 push/merge는 하지 않는다.

합성 테스트 통과는 실측 행동 정확도나 Pi 실기기 성능을 보장하지 않는다.

터치디스플레이에서는 화면 해상도·회전·터치 좌표·스크롤·문자 입력을 확인한다. 카메라는 실제 프레임과 수어 결과의 수신을, 스피커는 선택된 오디오 장치와 TTS 출력·중복 재생 방지를 확인한다. 센싱과 카메라를 동시에 켰을 때의 USB 전력·수신 공백·처리 지연도 측정한다.

## Windows에서 장비 없이 실행

`APP_LOCAL_PREVIEW=true`를 명시한 Windows 체험 빌드는 수어 홈과 센싱 페이지를 유지하면서 MQTT·카메라·재난 API의 자동 연결을 시작하지 않는다. 화면에 체험 모드를 표시하고, 실제 수어·안전 감지는 장비 미연결로 표시한다. 사용자가 센싱 페이지의 모의 신호 버튼을 누를 때만 synthetic CSI를 시작한다.

이 옵션의 기본값은 false이다. 실제 모드에서는 홈의 **연결 설정**에서 서비스 주소를 저장한다. 주소가 없으면 미설정 상태로 대기하고 저장하면 새 주소로 다시 연결한다. CSI는 `--real-only` 서비스에 연결하며 모의 신호를 사용할 수 없다. 자세한 실행 방법은 [실제 모드 안내](REAL_MODE.md)에 있다.

Windows 실행기는 별도 데이터 폴더를 사용하고, 앱 종료 시 자신이 시작한 센싱 서비스도 정리한다. 이 노트북의 Python 환경을 참조하는 로컬 실행본은 다른 PC 또는 Pi용 독립 배포 패키지가 아니다.

구현 후 [검사 결과](UI_INTEGRATION_VALIDATION.md)에 통과 항목과 미검증 범위를 기록했다. Notion 반영과 팀 검토는 후속 작업으로 남아 있다.
