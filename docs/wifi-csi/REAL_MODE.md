# 실제 장비 연결 모드

2026-10-04. 장비 주소를 앱에서 저장한 뒤 실제 서비스에 연결하는 실행 방식이다. 장비가 없어도 화면은 열리며, 수신한 데이터가 없으면 연결 대기로 표시한다. 장비 미연결 상태에서 실제 동작이나 정확도를 검증한 것은 아니다.

## 연결 설정

홈의 **연결 설정**에서 필요한 항목만 입력한다. 저장하면 화면이 홈으로 돌아오고, 입력한 서비스에 다시 연결한다. CSI 서비스는 같은 기기에서 별도로 계속 실행된다.

MQTT 브로커가 아직 꺼져 있으면 첫 접속 실패 후 3·6·12·15초 간격으로 재시도한다. 이후 간격은 최대 15초로 유지하며, 설정을 바꾸거나 앱을 닫으면 이전 접속 시도는 정리한다. 한 번 연결된 뒤 끊겼을 때는 MQTT 클라이언트의 재접속 기능을 사용한다.

| 항목 | 입력값 |
| --- | --- |
| MQTT | 브로커가 실행되는 Pi의 IP/호스트와 포트. 기본 1883 |
| 카메라 | 기존 RPi 카메라 스트림 서버의 IP/호스트와 포트. 기본 5000 |
| TTS | 음성을 생성하는 서버 URL. 스피커의 주소가 아님 |
| STT | 음성을 텍스트로 변환하는 서버 URL |
| 재난 API | 사용할 API URL과 키. 사용하지 않으면 비워 둠 |
| CSI 서비스 | 같은 기기에서 실행하는 bridge의 주소. 기본 127.0.0.1:8765 |

실제 장비를 사용하는 모드는 `APP_LOCAL_PREVIEW=false`로 빌드한다. 기존 MQTT 토픽/JSON과 카메라 프레임 형식은 바꾸지 않는다. 카메라 프로그램·MQTT 브로커·TTS/STT 서버는 각 장치에서 실행되어 있어야 한다.

일반 설정은 `SAFEHUB_CONFIG_FILE` 경로의 JSON에 저장한다. 해당 환경변수가 없으면 사용자 폴더의 `SafeHubData/connection-settings.json`을 사용한다. API 키는 같은 폴더의 `connection-settings.env`에 저장하고 JSON에서 제외한다. 프로세스의 `DISASTER_API_KEY` 환경변수가 있으면 파일보다 우선한다. 이 파일들은 Git에서 제외한다.

## CSI 수신

PC에서는 다음과 같이 실행한다.

```sh
python SW/wifi_sensing/bridge.py --real-only --allow-training --data-dir <측정기록_폴더>
```

Pi에서는 `--allow-training`을 제외한다. C6 TX에 전원을 공급하고 RX를 USB로 연결한 뒤, 앱의 와이파이 센싱에서 포트를 선택해 **실제 신호 연결**을 누른다. 실제 모드 화면은 `--real-only`로 실행한 서비스에만 연결한다. 모의 신호를 허용하는 서비스에 연결하면 주소 확인 안내를 표시하고 파형·인식 결과를 사용하지 않는다.

USB 목록은 약 3초마다 갱신한다. 포트가 여러 개면 사용할 RX 포트를 직접 선택한다. 같은 포트의 연결이 끊기면 서비스가 재접속을 시도하며, 포트 번호가 바뀌면 새 포트를 선택한다. 기록·모델 파일이 손상된 경우 해당 항목을 제외하고 화면에 경고를 표시한다. 원본 파일은 자동 삭제하지 않는다.

Windows 런처의 로컬 `config.json`에는 다음 두 항목을 추가한다. 나머지 필수 경로와 포트는 [Windows 빌드 안내](../../SW/windows_preview/README.md)를 따른다.

```json
{
  "real_only": true,
  "settings_file": "C:/실제경로/data/connection-settings.json"
}
```

런처는 `settings_file`의 존재를 확인한다. 처음에는 `{}`로 만들고 앱에서 주소를 입력할 수 있다. CSI 포트를 바꾸면 런처의 `port`와 앱의 `CSI_SERVICE_URL`도 같은 값으로 맞춘다. 준비한 로컬 Windows 실제 모드 실행본은 기존 체험본과 분리하기 위해 8766을 사용한다.

## 장비 연결 후 확인

- Pi OS와 아키텍처를 확인하고 ATLAS 또는 해당 OS용 앱을 빌드한다.
- 터치 좌표·해상도·스크롤을 확인한다.
- 카메라의 실제 영상과 MQTT 수어 결과 수신을 확인한다.
- TTS 서버와 스피커 출력을 확인한다.
- C6 수신률, 수신 공백, USB 재연결을 확인한다.
- 카메라와 CSI 동시 실행 시 지연·CPU/RAM·장시간 안정성을 측정한다.

CSI 판단의 전역 안전 경보 발행, 수동 가전 제어 버튼과 실제 액추에이터 연결은 별도 작업이다. 현재 가전 화면은 수신한 허브 명령을 표시하며 실제 기기 상태를 보증하지 않는다.
