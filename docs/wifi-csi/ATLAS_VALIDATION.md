# ATLAS 장치 검증

검증일: 2026-10-04. 대상은 RPi5·RPi4의 ATLAS 26.06.0-246, 기존 CSV 펌웨어를
사용하는 ESP32-C6 송수신기다. Windows 배포 ZIP은 별도의 고정된 릴리스이며,
이 문서의 Pi 설치 변경은 해당 ZIP에 포함되지 않는다.

## 확인한 내용

| 항목 | 결과 |
| --- | --- |
| RPi5 ARM64 Python 3.12.15 | 고정된 CSI 의존성 설치, `pip check` 통과 |
| CSI 테스트 | Windows 52개, RPi5 52개 통과. 테스트 입력은 합성/메모리 포트 |
| 실제 CSI | C6 CSV 입력, 처리 파형 생성, 관찰 수신률 약 58.8Hz |
| 출력 전용 수신기 | DTR/RTS 비활성화, 상태 명령 없이 연결 |
| RPi5 재부팅 | bootstrap·MQTT·CSI·UI 자동 시작, 추가 연결 명령 없이 실제 CSI 수신 |
| 실제 UI 조작 | 행동 추가·삭제, 8초 기록, 선택 기록 삭제·복원, ZIP 내보내기 확인 |
| 실제 기록 | 470프레임, 약 58.8Hz, 최대 프레임 간격 23ms. 점검용 기록은 휴지통으로 이동 |
| 행동 모델 | 기존 PC 학습 모델 가져오기, 실제 CSI 판단 표시, 시작·중지 확인 |
| RPi4 재부팅 | 기존 카메라·수어 서비스 자동 시작, Pi5 카메라 TCP 재연결 |
| MQTT 경로 | Pi4의 점검 메시지가 Pi5 알림·결과 칸에 표시됨. 이후 실제 파이프라인의 '괜찮다' 수신, '점등' 화면 표시 관찰 |
| MQTT 접근 제한 | Pi4의 CONNECT에 CONNACK 0, 미허용 노트북의 연결은 시간 초과 |
| 수집·학습 역할 | Pi에서 합성 입력과 학습 비활성화, 기존 MQTT Topic/JSON 유지 |

초기 ATLAS 설정에서는 `/data`의 unit 파일만 배치했을 때 부팅 시 서비스를
찾지 못했다. 루트의 bootstrap unit이 저장소 마운트 후 서비스를 불러오는
구성으로 수정하고 재부팅을 다시 검증했다. 루트 파일시스템은 설치 후 읽기
전용 상태로 복구했다. 설정 파일과 이전 서비스는 장치에 백업했다.

실제 앱에서 `/command/add_behavior?` 요청을 보냈을 때 서버가 `?`를 명령 이름에
포함시켜 거부하는 오류를 재현했다. POST 경로도 URL을 파싱하도록 수정했다.
수정 후 장치 화면에서 위 조작을 수행하고 저장 파일까지 확인했다. 빈 쿼리와
쿼리 파라미터가 있는 POST를 실제 HTTP 연결로 검사하는 회귀 테스트를 추가했다.

수어 점검 메시지는 실제 손동작 결과로 간주하지 않았다. 이후 카메라 파이프라인에서
나온 분류 결과의 전달도 관찰했지만, 수행자가 의도한 수어와 대조하지 않았으므로
수어 정확도 검증은 아니다. 화면·카메라 캡처와 사용자 모델은 공개 저장소에 넣지 않는다.

## 검증하지 않은 내용

- 사람이 수어를 수행하고 화면 자막과 비교하는 최종 사용자 시험
- 행동별 정확도, 낙상 오탐·미탐, 독립된 사람·장소·회차 평가
- 전원 완전 차단 후 복구, 물리 USB 재삽입과 tty 번호 변경
- 장시간 연속 운전, 전 구간 무선 패킷 유실률, CPU·온도 한계
- 외부 터치스크린의 모든 조작과 스피커·마이크 동시 운용

USB 지연 연결·재연결 로직은 메모리 포트 테스트로 검사했다. 이를 물리 USB
분리 시험으로 간주하지 않는다. 원래 수신기 로그 90줄이 초기 거부 수에
포함되었고 짧은 관찰 구간에서 이후 증가하지 않았다. 이 값은 RF 유실률이 아니다.

수어 자막 전송과 카메라 영상 경로는 노트북 MQTT 서버를 사용하지 않는다.
초기 음성 점검은 기존 노트북 HTTP 서버를 대상으로 했다. 이후 음성 입력은
Pi 내부의 스트리밍 STT로 전환했다. 현재 TTS는 네이티브 재생 실패 시 입력이
멈추는 문제 때문에 비활성화한 상태다. **앱 전체의 독립 음성 운용 완료로 보지 않는다**.
[ATLAS 음성 재생 제한](../../SW/safehub_app/atlas/README.md)을 참고한다.

기존 PC의 걷기·앉기·정지 모델을 복사해 Pi로 가져왔다. 원본 모델과 기록은 보존했다.
화면에 보이는 균형 정확도 68.0%는 이 모델의 과거 평가 기록이며 현재 설치 공간의
정확도가 아니다. 빈 공간 데이터를 학습하지 않았으므로 재실·부재 판단 모델로
사용할 수 없다.

설정과 복구 방법은 [ATLAS 부팅 설정](../../SW/atlas_boot/README.md)을 참고한다.

## 2026-10-04 경보 통합 · 연속 음성 자막

- Pi5의 기존 재난 카드 위치를 자동 음성 자막으로 교체하고 오른쪽 경보 카드에 재난 요약·상세 보기를 통합했다.
- 서비스/화면/HTTP/알림/녹음 어댑터 관련 테스트 32개 통과. 1920×1080, 1024×600, 800×480, 600×800 배치를 확인했다.
- Pi5 ATLAS에서 새 화면 표시와 자막 일시정지·재시작을 원격 입력으로 확인했다. 물리 터치의 접촉 안정성 시험을 대체하지 않는다.
- 실제 `parecord` 프로세스 하나가 16 kHz mono PCM을 공급한다. CSI는 live 모드와 기존 모델 추론을 유지하고 기록 47개를 보존했다.
- 사용자가 팀 음성 서버 `165.229.125.111:8000`을 확인했다. 노트북과 Pi5에서 해당 서버 연결이 시간 초과되어 실제 음성→자막 변환과 지연은 아직 검증하지 못했다.
- 자동 자막은 기존 multipart `/stt`에 짧은 구간을 보내는 방식이며, 글자 단위 스트리밍이 아니다. 임시 대체 서버는 실행하지 않았다.

후속 확인: 팀 서버 `165.229.125.111:8000`의 연결이 복구되어 PC와 Pi5 모두 `/health` HTTP 200 및 모델 ready를 확인했다. 팀 TTS에서 생성한 한국어 음성을 `/stt`로 전송해 실제 변환 결과를 받았다(요청 응답 11.03초). 이는 생성 음성의 API 시험이며 물리 마이크 입력부터 화면 자막까지의 검증과 구분한다. `165.229.125.107`은 Pi5 앱 호스트이며 8000번 음성 서버가 실행되고 있지 않다.


## 음성 구간 경계 비교

사용자가 제공한 한국어 예문을 팀 TTS로 생성한 7.416초 오디오로 비교했다. 전체 음성의 STT 결과는 예문과 일치했고 응답은 1.88초였다.
같은 오디오를 6초에서 잘라 보냈을 때는 `청각장애인`이 `청각장의 인과`로, 마지막 `STT입니다`가 분절되어 `S2.`, `보수입니다.`로 인식됐다.
이는 생성 음성 한 문장의 구간 분할 비교이며 실제 마이크의 정확도 수치로 해석하지 않는다.

클라이언트는 중간 결과 2.4초, 종료 침묵 0.8초, 최대 구간 12초, 시작 전 보존 0.4초로 조정했다.
마이크 DC offset이 음성 감지 기준을 지속해서 넘지 않도록 약 20 Hz DC 차단 필터를 추가하고 중간 결과에 임시 자막 상태를 표시한다.
팀 서버의 base 모델과 API는 변경하지 않았다. 실제 대화에서의 문장 오류율과 마이크 배치별 성능은 추가 확인이 필요하다.

수정본 배포 후 Pi5 홈 화면에서 실제 마이크를 통한 대화 자막 표시까지 확인했다. 발화 원문과의 대조가 없으므로 실측 정확도 개선을 확정한 것은 아니다.

## 현재 로컬 STT와 ThinQ 상태

위 HTTP 구간 비교 이후, Pi 내부의 sherpa-onnx 한국어 스트리밍 모델로 전환했다.
서버는 루프백에만 바인딩하며 PCM을 연속 처리한다. 설치 방법, 고정 버전,
시험 음성 측정값과 한계는 [로컬 STT](../../SW/local_stt/README.md)에 기록했다.
RPi4의 STT 성능과 실제 대화 정확도는 미검증이다.

Home Assistant 설치와 LG ThinQ 토큰 설정을 완료했지만, ATLAS Cloud Gateway의
ThinQ 계정 등록은 완료하지 못했다. 가전 완료 이벤트가 SafeHub에 들어오는 상태는
아니다. [설치·연동 상태](../home-assistant/STATUS.md)를 참고한다.
