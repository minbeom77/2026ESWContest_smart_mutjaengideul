## 발견한 오류와 수정

직전 develop에 새 회귀를 실행하니 아프다/구조/쓰러지다는 도움 창만 열고 장치 전달용
`onScenarioAlert`를 호출하지 않았다. 3개 실패와 같은 콜백을 사용하는 방송 대조 1개 통과를 확인했다.
기존 289개 검사 통과는 이 빠진 경로를 검증하지 않았다.

#18의 전달 콜백과 확인 수어의 공통 정리 경로를 합쳤다. 같은 수어 반복으로 명령을 중복 요청하지
않으며, 괜찮다 응답은 해당 사건 정리/대기 알림 처리를 호출한다.
추가로 화면의 괜찮아요도 도움 사건의 정리 콜백을 호출하도록 고쳤다. 도움 취소 아래에
화재/재난이 열려 있다면 그 사건을 무조건 확인 처리하지 않는다.

전달/확인 회귀 5개와 터치 정리·동시 화재 보존 2개를 추가했다.
실제 장치 동작을 측정한 검사가 아니라는 점을 유지한다.

## Uno 원본 탐색과 외부 자료

팀 원격과 명준/학진의 공개 fork 총 47개 브랜치 tip, 그 refs로 추적 가능한 Git 이력에서
`.ino`/`.pde`/`.hex`·Arduino/sketch 파일명과 Serial/핀 제어 코드 패턴을 검색했다.
Uno 연동 커밋 `a5c910b`도 직접 확인했으나 Python 브리지와 문서만 있었다.
현재 확보한 공개 소스에서 운영 Uno 스케치를 찾지 못했다. 개인 PC/장치/비공개 보관본에 없다는
뜻은 아니다. 실제 원본이 확보되기 전까지 임의 펌웨어를 운영 원본인 것처럼 추가하지 않는다.

모델·SDK·펌웨어·설정의 재현 조건과 알려진 해시는 [REPRODUCIBILITY](../REPRODUCIBILITY.md)에 기록한다.
알려진 위치와 작성자 보고를 확보한 것과 현재 장치 직접 확인을 구분한다.
Pi4/Pi5 접속은 클라우드에서 connection refused였으므로 현재 `/proc/PID/exe`/kernel/모델을
직접 대조하지 못했다. 1.5.16 설치와 UART 관찰은 #18 작성자 보고이며 물리 동작 보장이 아니다.

## 병합/제출

일반 코드 수정·검사·작업 브랜치 push와 develop 통합은 사용자의 기존 지시 범위다.
검증한 후보를 develop에 반영하면 기존 #17의 head/diff가 갱신된다.
main 최종 병합은 별도 사용자 지시 단계로 남긴다. 최종 SHA·CI·source ZIP metadata를 함께 확인한다.
main은 현재 제품 소스 한 벌을 보여주고 과거 브랜치/복구 이력은 보존한다.
