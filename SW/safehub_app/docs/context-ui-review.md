# SafeHub 맥락 기반 UI 변경

기준: feature/voice-server-port의 d943a96. 작업 브랜치: feature/safehub-site-ui.

디자인 참고: https://safehub-ui-demo.royal-rook-2899.chatgpt.site
별도 웹사이트의 디자인을 Flutter 위젯으로 구현한 변경이다.

## 구현 범위

- 거실 사진 배경, 따뜻한 반투명 패널, 크림색 본문과 산호색 동작으로 홈·대화·설정 화면 재구성.
- 홈: 최근 이벤트, 카메라/메시지 허브 연결, CSI 상태 미연동 표시, 마지막 재난 조회 상태.
- 대화: 카메라, 수어 원문, STT 원문, 최신순 최근 100개 대화 기록(메모리만 사용).
- 수어 자동 읽기 토글, 다시 읽기, STT 녹음 중 TTS 자동 재생 억제.
- ‘아프다’는 ‘아파요.’로만 읽고, 도움 요청은 별도 선택으로 확정.
- 낙상 의심: 사건별 응답 상태와 10/30/60초 대기 설정(기본 30초, 시연용).
- ‘괜찮아요’는 현재 사건만 종료. ‘도움이 필요해요’/시간 초과는 로컬 요청만 생성.
- 가족 알림이 실제로 전송되지 않았음을 표시. 가족 서버·LED·베드셰이커 호출은 구현하지 않음.
- 기존 가전/단축키 패널은 설정으로 이동.
- UI 테스트 모드에서 외부 서비스 연결과 재난 조회를 생략하고 테스트 입력 제공.
- MQTT 수신 코드는 기준 브랜치 그대로 유지: message_id 기준 최근 2000개 중복 방지 및 자동 재연결.

## 중요한 경계

- PowerShell/MQTT 테스트를 실제 CSI 감지 검증으로 표시하지 않는다. 테스트 이벤트는 source: ui_test를 넣는다.
- 센서 heartbeat가 없으므로 MQTT 연결과 센서 상태를 구분한다.
- 수어 메시지는 현재 text만 전달되어 사건 ID/촬영 시각을 검증할 수 없다. 수어만으로 경보를 자동 해제하지 않고 버튼으로 확인한다. 자동 응답은 HW팀과 신선도/사건 연결 규약을 정한 뒤 확장한다.
- 타이머는 사건 수신 시 시작하며, 다른 경보 뒤에서 대기하는 사건도 별도로 추적한다.
- 모든 요청/대화/응답은 앱 메모리에만 있다. 재시작 후 복원이나 실제 가족 전송 큐가 아니다.
- LLM, 영상통화, GRU, 센서 모델, 실제 액추에이터 제어는 이번 UI 변경에 포함되지 않는다.
- ‘취소’는 아직 전송되지 않은 로컬 요청을 지운다는 뜻이다.

## RPi 개발 환경에서 확인

기존 Atlas Flutter SDK와 `/opt/flutter-atlas-plugins` 의존성이 준비된 환경에서 실행한다.
기존 빌드/실행 명령에 `--dart-define=SAFEHUB_UI_DEMO=true`를 추가하면 테스트 모드가 된다.
실기기 연결에는 이 플래그를 제거하고 기존 MQTT/CAMERA/STT/TTS/재난 API 설정을 유지한다.

```sh
flutter analyze
flutter test
```

SDK 실행 파일 이름이 다른 환경은 해당 SDK 명령으로 바꾼다.

확인 순서:
1. 연결이 끊긴 상태에서 ‘안전’으로 표시되지 않는지 확인.
2. 수어 ‘아프다’ → 도움 선택 → 전송 미연결 표시.
3. ‘괜찮다’ 수어만으로 낙상 알림이 닫히지 않고, 버튼 응답 후 종료되는지 확인.
4. 낙상 테스트 → 시간 초과 → 미응답 요청 → 늦은 ‘괜찮아요’ 응답으로 로컬 요청 해제.
5. 서로 다른 사건 2개를 보내 첫 응답이 두 번째 사건을 종료하지 않는지 확인.
6. 기존 MQTT 테스트로 message_id 재전송 중복 방지 확인.
7. STT 녹음 시작/종료와 TTS 자동 읽기, 경보 시 녹음 중단을 실제 헤드셋으로 확인.
8. 1280×720, 1920×1080 및 터치 화면에서 긴 문장/설정/경보 스크롤 확인.

## 현재 검증

- Dart 구문 파서 검사 및 git diff --check 수행.
- 의미 있는 사건별 timeout/응답 테스트 추가. Flutter/Atlas SDK 부재로 테스트 실행 및 Flutter analyze/build는 미수행.
- 대화 내 HTML 미리보기는 Flutter 실행 화면 캡처가 아닌 동일 방향의 상호작용 시안이다.

## 이어서 반영한 보완

첨부 개발계획서의 의사소통 지원, 재난 원문 표시, 인식/네트워크 문제에 대응하는 흐름을 참고했다. 실제 장비 구성(RPi4 수어·RPi5 총괄)과 KNN 유지 결정은 변경하지 않았다.

- ‘가족이 와 주세요’ / ‘가족과 통화하고 싶어요’ 선택 → 규칙 기반 전달 문장 미리보기 → 요청 생성.
- 도움 선택을 시작한 수어와 사건을 고정해 이후 카메라 결과나 새로운 사건으로 요청 내용이 바뀌지 않게 처리.
- 요청 완료/닫기 후 15초 동안 같은 ‘아프다’ 입력이 도움 창을 반복해서 띄우지 않도록 억제.
- STT/수어가 잘 안 될 때 직접 입력(최대 500자)으로 대화 기록에 추가. LLM 교정은 미적용.
- 영상 프레임을 5초 이상 받지 못하면 ‘영상 수신 중’ 표시를 해제하고 오래된 정지 영상을 숨김.
- 재난 알림: 어두운 화면, 재난 원문, 대상 지역, 발표 시각, ‘내용 확인했어요’. 전체 화면 점멸 제거.
- 입력창/가전 설정 색상도 기본 화면과 일치하도록 조정.
- 로컬 도움 요청에 공간/사건 수신 시각 표시. 타임아웃 요청을 취소한 후 자동 재생성되던 문제 수정.
- STT 시작 또는 안전 알림 이후 취소된 TTS가 뒤늦게 재생되지 않도록 재생 직전 상태 재확인.
- 재난 문자 UI 테스트 버튼 추가. 모든 테스트 입력은 실제 장치 감지 또는 실제 API 조회를 뜻하지 않음.

이 실행 환경에는 Flutter/Atlas SDK가 없다. 이번 추가 변경의 Flutter analyze/test/build 및 실기기 검증은 아직 수행하지 못했다. Dart 구문 파서 검사와 패치 공백 검사는 통과했다. 구문 검사는 Flutter 의미 분석이나 빌드 검사를 대체하지 않는다.

추가 UI 회귀 검사: `flutter test test/context_ui_test.dart test/care_incident_test.dart test/sign_speech_policy_test.dart`
홈→대화 이동, 두 낙상 사건의 독립 응답, 시간 초과 이후 늦은 응답을 검사한다. 테스트 코드는 추가했으며 Atlas SDK에서 실행해야 한다.

## 실기기 사진 확인 후 보완

- 패널 불투명도를 높이고 메뉴·동작 버튼과 본문 크기를 확대.
- 대화 카메라 높이를 화면 높이에 맞춰 제한하고 음성 녹음 버튼을 자막 옆으로 이동.
- 지난 대화는 접어서 현재 수어·음성 자막과 주요 버튼에 공간을 배정.
- 홈에 침실·화장실별 마지막 수신 이벤트 표시. 수신이 없으면 센서 상태 미확인 표시.
- 실행 스크립트의 기본 카메라 주소를 현재 장비 IP 192.168.0.4로 수정. CAMERA_HOST 환경변수로 변경 가능.
- 장치 연결 패널에 빌드된 카메라 주소 표시. TCP 연결과 영상 수신을 구분하며 실제 카메라 복구 여부는 실기기 로그로 확인해야 함.

## 최종 디자인 선택: 기존 대시보드 유지

실기기 화면을 비교한 사용자의 선택에 따라 d943a96의 3열 홈, 큰 카메라 의사소통 화면, 원래 가전 패널 배치를 복원했다. 사이트의 홈·대화·설정 배치는 사용하지 않는다.

추가 기능 위치:
- 홈 수어 패널의 손 아이콘: 도움 종류 선택 및 로컬 요청.
- 상단 설정 아이콘: 낙상 응답 대기 시간, 미전송 도움 요청 확인·취소.
- 의사소통 수어 결과: 자동 읽기 토글, 다시 읽기, 도움 선택.
- 음성 → 텍스트 패널: 직접 입력 및 대화 기록 버튼.
- 낙상 알림: 괜찮아요 / 도움이 필요해요, 사건별 타이머와 다음 사건 독립 처리 유지.

카메라의 오래된 프레임 숨김, MQTT message_id 중복 방지, STT/TTS 시간 제한을 유지한다. 카메라 기본 주소는 192.168.0.4이며, 영상 수신 복구 여부는 장치에서 별도로 확인해야 한다.
